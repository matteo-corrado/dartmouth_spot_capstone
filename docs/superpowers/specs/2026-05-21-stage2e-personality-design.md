# Stage 2E Design — Personality System (TTS A/B + Multi-Persona + Mouth + Scene Comments)

> **Status:** Plans 2A–2D written but not yet executed. Branch `tour_guide_upgrade_matteo` at tag `stage1.5-complete`. Stage 2E ships on top of current `main` (Ollama brain, current TTS, current ASR state) to hit a hard demo schedule (Tue/Thu 2026-05-26 / 2026-05-28). 2E is **input-agnostic and brain-agnostic** — it composes cleanly with the future 2A llama.cpp + Parakeet stack without re-design.

## Goal

Bring Spot from "voice-controlled robot" to "robot with personality." Three deliverables, ship-fast slices:

1. **Tuesday 2026-05-26** — Multi-personality routing, runtime persona swap by voice command, two TTS backends (Kokoro v1.1 multi-lang local + ElevenLabs Flash v2.5 cloud) swappable via env var. Live on Spot.
2. **Thursday 2026-05-28** — Gripper-as-puppet mouth animation synchronized to TTS audio. Optional arm gaze toward nearest person.
3. **Later (post-Stage-2C)** — Continuous YOLO-gated VLM scene commentary loop with persona-voiced quips.

The "Boston Dynamics chat" demo as a target: BD used GPT-4 + BLIP-2 + ElevenLabs + a gripper-mouth puppet trick. We rebuild the same theatrical experience on local + permissive-license infrastructure with a swappable cloud TTS for the wow factor.

## Cross-cutting decisions

### Schedule pressure overrides "wait for 2A"

Stage 2A (voice pipeline) is 84 tasks and cannot ship before Tuesday. 2E is designed to compose cleanly with current `main` (Ollama brain + current ASR state) AND with the future llama.cpp + Parakeet stack. No interface in 2E breaks when 2A lands; 2A's gbnf grammar just gains a `set_persona` entry mirroring the JSON action shape we define here.

If voice input is unreliable on `main` at demo time, the Tuesday demo runs via the existing web panel (text in, voice out) — the persona swap + TTS A/B is fully demonstrable without the mic chain.

### TTS — Kokoro v1.1 (local) + ElevenLabs Flash v2.5 (cloud), swappable

Two backends behind a `TTSBackend` Protocol, dispatched by `SPOT_TTS_BACKEND={kokoro|elevenlabs}`.

**Kokoro v1.1 multi-lang** (default local) — drop-in upgrade from current `kokoro-en-v0.19`. 103 voices in v1.1 vs 8 in v0.19, same sherpa-onnx infrastructure, Apache 2.0, <1 GB VRAM, <500 ms warm latency. Free upgrade — no new install pain.

**ElevenLabs Flash v2.5** (premium cloud) — `model_id="eleven_flash_v2_5"`, WebSocket streaming (`/v1/text-to-speech/{voice_id}/stream-input`), `output_format="pcm_24000"` to skip mp3 decode, `optimize_streaming_latency=3`, `chunk_length_schedule=[120, 160, 250, 290]`, `flush:true` at turn end. Real-world TTFA 150–300 ms per independent Coval benchmark (May 2026). 1000+ voices including cloning; we use stock voices only for Tuesday.

**Considered and rejected for now:**

- **Chatterbox-Turbo** (MIT, won 63.75 % blind tests vs ElevenLabs, listed in `jetson-containers` so install is plausible) — deferred. Adds a third backend with install risk on Jetson AGX Orin (PyTorch pin workaround needed: `pip install chatterbox-tts --no-deps`). Bring in later if quality of the two-backend lineup falls short.
- **Cartesia Sonic-3 / Turbo** (40–100 ms TTFB, lowest commercial latency) — deferred. User does not currently have an API key; adding a third vendor is not justified for Tuesday.
- **VoXtream2 / TADA / Sesame Maya / F5-TTS / XTTS v2 / Fish Speech / Bark / Piper** — rejected: too slow for live, license blocks commercial robotics, hardware too heavy for Jetson, or already dominated by Kokoro v1.1 in our use case.

### Persona swap trigger — env-var default + runtime action (option C from brainstorm)

`SPOT_PERSONA` env var sets the boot-time persona. A `set_persona(name)` action — emitted by the LLM when it detects intent like *"be a pirate"*, *"switch to butler mode"*, *"be yourself"* — mutates session state at runtime. This combines the repeatability of env-var-fixed personas (clean A/B comparisons across boots) with live-demo flexibility (*"switch to pirate"* mid-tour). Persona persists across utterances until next swap or explicit reset.

Persona swap acknowledgement is generated by the LLM under the NEW persona's prompt prefix and spoken in the NEW voice. So *"switch to pirate"* yields something like *"Aye captain, pirate mode engaged!"* in the pirate voice — no awkward old-voice ack before the new voice kicks in.

### State — two-layer model

Current `get_robot_state_dict()` (`spot_dispatch.py:80`) is a per-turn live SDK snapshot — battery, location, estop, maps. It's already rendered as a `"- key: value"` bullet list and appended to `SYSTEM_PROMPT` in `_build_messages()` (`llm_brain.py:273`). This is structurally BD-style state grounding already; we keep the format.

We add a second layer for *conversational* state (persists across turns):

```python
@dataclass
class SessionState:
    current_persona: str = "tour_guide"
    turn_index: int = 0
    last_action_taken: Optional[str] = None
    last_comment_ts: float = 0.0
    # 2E.2 adds: arm_deployed, gaze_target, person_present, person_count
    # 2E.3 adds: last_yolo_classes, last_vlm_caption, last_uttered_phrase

    def as_dict(self) -> dict:
        return {
            "current_persona": self.current_persona,
            "turn_index": self.turn_index,
            "last_action_taken": self.last_action_taken or "none",
            "seconds_since_last_comment": int(time.time() - self.last_comment_ts),
        }
```

Both layers merge into the single bullet-list block; the persona's `prompt_prefix` goes BEFORE `SYSTEM_PROMPT` because it sets *who you are* — a different concern from the "where am I, what just happened" state lines.

Existing `is_standing` field is currently hardcoded `"unknown"` and never assigned. 2E.1 optionally wires it to `robot_state.kinematic_state.behavior_state` while the file is open. Also optionally adds `nearby_locations` (graph-edge neighbors of current waypoint) for tour-guide spatial quips. Both are nice-to-haves, not blocking.

### Persona registry — declarative YAML, hot-reloadable

```yaml
# config/personas.yaml — append new entries to add personas
tour_guide:
  prompt_prefix: "You are a knowledgeable, warm Dartmouth College tour guide..."
  voices:
    kokoro_v1: af_sarah
    elevenlabs: 21m00Tcm4TlvDq8ikWAM
pirate:
  prompt_prefix: "You are a salty pirate captain. Speak in nautical slang..."
  voices:
    kokoro_v1: am_fenrir
    elevenlabs: pNInz6obpgDQGcFmaJgB
# ... (6 starter personas: tour_guide, pirate, snarky, butler, shakespeare, gen_z)
```

Costs to add a new persona post-design: ~5–10 minutes (pick voice IDs by listening, draft 1–2 sentence prompt prefix). No code change required. Hot-reload via SIGHUP.

Invalid persona name in `set_persona(name)` falls back to default (`SPOT_PERSONA` env value or `tour_guide`) and logs a warning. Robust against LLM typos.

## Non-goals

- No backwards-compat shims for Stage 1 paths.
- No new mic hardware. Audio input chain stays whatever Stage 2A inherits.
- No Spot SDK upgrade (stay on `bosdyn-client==5.0.1.1`).
- No persona-aware action behavior changes — a pirate-personality Spot still navigates the same way as the default; only its words and voice change. Persona-aware nav is a future enhancement.
- No voice cloning in 2E.1 — stock voices only. Cloning ships later via Chatterbox-Turbo or ElevenLabs Instant Voice Clone if useful.

## §5 — Slice 2E.1: TTS multi-voice + multi-persona routing

### 5.1 Goal

Tuesday-shippable. Two TTS backends behind one env-var flag. Six personas with per-backend voice mapping. Runtime persona swap by voice command via a new `set_persona` action. Persona prefix injected into every brain call. Conversation log writes per-turn JSONL.

### 5.2 Components

**TTS backend interface** — `src/voice_control/tts/__init__.py`:

```python
class TTSBackend(Protocol):
    def synthesize(self, text: str, voice_id: str) -> bytes: ...
    def stream(self, text: str, voice_id: str) -> Iterator[bytes]: ...
    def list_voices(self) -> list[VoiceInfo]: ...
```

**Kokoro backend** — `src/voice_control/tts/kokoro.py`. Wraps existing sherpa-onnx Kokoro loader. Model swap from `kokoro-en-v0.19` → `kokoro-multi-lang-v1_1` (103 voices). Voice ID = sherpa-onnx speaker slug (e.g. `af_sarah`, `am_fenrir`, `bm_george`).

**ElevenLabs backend** — `src/voice_control/tts/elevenlabs.py`. Uses official `elevenlabs` Python SDK's `text_to_speech.stream()` for HTTP streaming. WebSocket streaming endpoint (`/v1/text-to-speech/{voice_id}/stream-input`) used for lowest TTFA. Settings: `model_id="eleven_flash_v2_5"`, `output_format="pcm_24000"`, `optimize_streaming_latency=3`, `chunk_length_schedule=[120, 160, 250, 290]`, `flush:true` at sentence end. API key from `ELEVENLABS_API_KEY` env.

**Dispatch** — `src/voice_control/tts/__init__.py` exposes `get_backend()` reading `SPOT_TTS_BACKEND={kokoro|elevenlabs}` (default `kokoro`). `src/voice_control/spot_tts.py` calls `get_backend()` and routes synth requests.

**Persona registry** — `src/voice_control/chatbot/persona.py`. Loads `config/personas.yaml` at boot. Exposes `get_persona(name) -> Persona`, `list_personas() -> list[str]`, `default_persona() -> str` (reads `SPOT_PERSONA` env, defaults to `tour_guide`). Hot-reloads on SIGHUP. Invalid lookups fall back to default + warn.

**SessionState dataclass** — `src/voice_control/chatbot/session_state.py`. Fields: `current_persona`, `turn_index`, `last_action_taken`, `last_comment_ts`. Owned by the `LLMBrain` instance, mutated by dispatcher actions, rendered via `as_dict()` into the existing bullet-list state block.

**Prompt assembly** — Modify `LLMBrain._build_messages()` (`llm_brain.py:273`):

```python
def _build_messages(self, transcript, robot_state, session_state):
    persona = get_persona(session_state.current_persona)
    merged_state = {**robot_state, **session_state.as_dict()}
    state_lines = "\n".join(f"- {k}: {v}" for k, v in merged_state.items())
    system_content = (
        f"{persona.prompt_prefix}\n\n"
        f"{SYSTEM_PROMPT}\n\n"
        f"Current robot state:\n{state_lines}"
    )
    # ... (history + user message append as today)
```

**Action: `set_persona`** — Added to dispatcher's action handler table. Schema:

```json
{"action": "set_persona", "params": {"name": "pirate"}}
```

Handler updates `session_state.current_persona` and returns. LLM generates the acknowledgement under the NEW persona's prefix on its next turn (or in the same turn if the LLM emits both `set_persona` and a response together). Invalid name → fallback to default + log warning.

System prompt augmentation — append a small block listing available persona names and intent examples so the LLM knows when to emit `set_persona`:

```
- set_persona: Switch the robot's personality. Params: {"name": "<persona_name>"}.
  Available personas: tour_guide, pirate, snarky, butler, shakespeare, gen_z.
  Emit when the user says things like "be a pirate", "switch to butler mode",
  "be yourself" (resets to tour_guide), etc.
```

**Conversation log** — `src/voice_control/chatbot/conversation_log.py`. One JSONL line per turn:

```json
{"ts": 1748275200.123, "persona": "pirate", "tts_backend": "elevenlabs",
 "voice_id": "pNInz6obpgDQGcFmaJgB", "transcript": "what's that over there?",
 "response": "Arr, a chair and laptop, ye landlubber!", "actions": [],
 "latency_ms": {"asr": 230, "llm": 1820, "tts_first_chunk": 280}}
```

Writes to `logs/conversations/<YYYY-MM-DD>.jsonl` (already symlinked to SSD per Stage 1.5). Daily rotation.

**Config**:

- `MAX_HISTORY = 12 → 24` (longer context helps persona consistency across turns).
- `SPOT_TTS_BACKEND` env var, default `kokoro`.
- `SPOT_PERSONA` env var, default `tour_guide`.
- `ELEVENLABS_API_KEY` env var, required only when `SPOT_TTS_BACKEND=elevenlabs`.

### 5.3 Personas — starter pack (6)

| Name | Voice intuition | Use |
|---|---|---|
| `tour_guide` (default) | warm female (Kokoro `af_sarah` / ElevenLabs Rachel) | Default Dartmouth guide |
| `pirate` | gravelly male (Kokoro `am_fenrir` / ElevenLabs Adam) | Demo wow factor |
| `snarky` | flat male (Kokoro `am_onyx` / ElevenLabs Charlie) | BD's "snarky unhelpful robot" reference |
| `butler` | British male (Kokoro `bm_george` / ElevenLabs Daniel) | Formal counterpoint |

### 5.4 Demo plan

Tuesday demo runs against Spot live (or via web panel if mic chain not ready). Demo script:

1. Boot with `SPOT_TTS_BACKEND=kokoro` and `SPOT_PERSONA=tour_guide`. Spot greets in Kokoro voice.
2. *"Be a pirate."* → Spot switches voice + persona, acknowledges in pirate voice.
3. *"Describe yourself."* → Pirate-flavored self-description.
4. *"Switch to butler."* → Persona swap to butler voice.
5. *"Be yourself."* → Reset to tour_guide.
6. Reboot Spot with `SPOT_TTS_BACKEND=elevenlabs`. Repeat steps 1–5. Compare voice quality across backends.
7. Edit `config/personas.yaml` to add a new persona on the fly; SIGHUP the process. Demonstrate new persona via voice command.

### 5.5 Risks

- **ElevenLabs free tier** is 10 k chars/month. Easy to burn during dev. Mitigation: route a small `tts_token_budget.py` counter into the logs so we can monitor; cache rendered phrases in `logs/tts_cache/` keyed by `(backend, voice_id, text)` so re-runs don't re-spend.
- **Persona drift in long conversations** — with `MAX_HISTORY=24` plus persona prefix, the prefix may get overshadowed after 12+ turns. Mitigation: re-inject persona prefix into every turn's system message (already the design — confirms intent).
- **Kokoro v1.1 model compatibility** — sherpa-onnx Kokoro loader is the same; only the model archive changes. Smoke-test the v1.1 download before scoping any other risk.
- **Persona name disambiguation** — LLM might say *"be a pirate captain"* and our intent classifier needs `pirate` not `pirate captain`. Mitigation: fuzzy-match against registry keys + fallback warning.

### 5.6 Out of scope for 2E.1

Gripper mouth, VLM scene loop, cloud brain backends, Tavily web_search, FactsStore SQLite. Voice cloning. Chatterbox-Turbo backend. Persona-aware nav behavior.

## §6 — Slice 2E.2: Gripper puppet mouth + gaze

### 6.1 Goal

Spot's gripper opens and closes in sync with TTS audio, BD-style. Optional: arm points toward closest detected person while speaking.

### 6.2 Components

**PCM envelope** — `src/voice_control/animation/mouth.py`. IIR lowpass filter (scipy.signal `lfilter` with cutoff ~50 Hz) over chunked TTS PCM samples (24 kHz from Kokoro/ElevenLabs). Yields amplitude envelope at ~20 Hz. Maps envelope value → `gripper_open_fraction ∈ [0.0, 1.0]` linearly with a noise gate (silence keeps gripper closed).

**Arm streaming** — `bosdyn-client` `ArmCommand` builder with `RobotCommandClient` streaming. Sends `gripper_open_fraction` commands at ~20 Hz synchronized to audio playback timestamps. Safe pose: arm deployed at ~45° forward, gripper at chest height, away from collision-likely volume.

**Sync** — TTS streams PCM chunks into both the audio player (existing) AND the envelope extractor in parallel. Envelope extractor pushes gripper commands onto a queue consumed by the arm thread. Latency-budgeted: gripper movement should lead audio by at most ~50 ms.

**Gaze (optional within slice)** — `src/voice_control/animation/gaze.py`. Queries `WorldObjectClient.list_world_objects()` filtered by detected-object person type at ~1 Hz. Picks closest person, computes yaw to that point, issues `ArmCartesianCommand` to orient the gripper toward them. Refreshes during speech.

**SessionState additions**:

- `arm_deployed: bool` — guard against gripper commands when arm is stowed.
- `gaze_target: Optional[tuple[float, float, float]]` — body-frame XYZ of current gaze target, or None.
- `person_present: bool` — at least one person detected.
- `person_count: int` — number of detected people.

**Action: `enable_mouth`** / **`disable_mouth`** — runtime toggle. Defaults to enabled; voice command *"stop moving your mouth"* sets it off.

### 6.3 Mandatory feasibility spike (before plan exec)

bosdyn streaming `gripper_open_fraction` at audio rate is unverified on our setup. 1-hour spike:

1. Power Spot, deploy arm, position safely.
2. Send `ArmCommand` with `gripper_open_fraction` modulated by a 5 Hz sine wave for 30 s.
3. Measure: actual command rate (does SDK rate-limit? what cap?), jitter, smoothness of gripper movement.
4. Repeat at 10 Hz, 20 Hz, 30 Hz to find the practical ceiling.

If rate-limited below ~10 Hz: fallback to syllable-boundary open/close (less smooth, still puppet-like). Use sherpa-onnx Kokoro's word/phone timestamps or ElevenLabs alignment metadata to drive syllable triggers.

### 6.4 Risks

- **Streaming rate cap (highest)** — see spike above.
- **Battery** — arm deployed throughout demo. Budget ~30 min before swap; demo script accommodates.
- **Collision with people** — arm extended near humans. Soft deployed pose (no fast lateral motion), velocity caps on `ArmCartesianCommand`, e-stop in operator's hand.
- **TTS / arm desync drift** — clock drift across audio chunks → gripper trails or leads audio. Mitigation: timestamp each PCM chunk and each arm command from the same monotonic clock; resync on each chunk boundary.
- **Persona vs animation mismatch** — pirate persona expects bigger mouth swings than butler. Map: per-persona `mouth_intensity` multiplier in `personas.yaml` (`0.7` for butler, `1.3` for pirate).

### 6.5 Demo plan

Thursday demo: any utterance from Tuesday's persona set, with gripper visibly synced. Bonus: arm tracking nearest person during speech.

## §7 — Slice 2E.3: VLM scene-comment loop + gaze (sketch)

### 7.1 Goal

Spot notices objects in its environment and remarks on them in-character — BD's "robot tour guide" core trick — without requiring the user to ask.

### 7.2 Approach (high level)

- **YOLO inventory** — YOLO26-N (TRT FP16 engine from Stage 2C) at ~5 Hz across 5 cameras (fronts undistorted via Stage 2C). Tracks the current set of detected object classes.
- **Interest gate** — fires when (a) class-set changes (new class appeared) OR (b) 30 s tick OR (c) the LLM specifically requests a YOLOE26 open-vocab query.
- **Barge-in protect** — skip if user is speaking, TTS is playing, or robot is currently navigating.
- **Trigger handler** — calls llama-server's multimodal endpoint (gemma4:e4b + `mmproj-BF16.gguf`, both shipped by Stage 2A) with: current frame, YOLO class list, persona prefix, and a "make ONE short in-character remark or return empty if nothing interesting" prompt. Empty → skip TTS. Non-empty → speak via current TTS backend + persona voice.
- **Rate limit** — min 15–30 s between comments. `last_comment_ts` field in `SessionState` already in place (added in 2E.1) — no schema change needed.

### 7.3 Dependencies (hard ordering)

- Stage 2A — llama-server with `mmproj` for multimodal calls. Without 2A, no in-house VLM path; would need to fall back to cloud (2E.4).
- Stage 2C — YOLO26-N TRT engine + fisheye undistort. Without 2C, YOLO on raw fisheye is unreliable.
- Stage 2E.1 — persona infra + TTS abstraction (this spec).

### 7.4 Risks (sketched, deferred to per-plan)

- gemma4 vision quality on lab photos — 30-min spike with 10 representative scenes before commit.
- VLM call stacks latency with TTS — total end-to-end "scene noticed → comment audible" should stay under ~3 s.
- Audio/visual barge-in protocol — if user speaks mid-comment, kill TTS gracefully and revert to listening.

## §10 — Rollback layers

Each slice ships with a single env-var override that reverts it:

| Slice | Env var | Effect |
|---|---|---|
| 2E.1 TTS | `SPOT_TTS_BACKEND=kokoro` | Revert from ElevenLabs to local Kokoro |
| 2E.1 persona | `SPOT_PERSONA=tour_guide` | Reset to single default persona; `set_persona` actions still execute but always resolve to default if other personas removed from yaml |
| 2E.2 mouth | `SPOT_MOUTH_ENABLED=0` | Skip gripper animation; TTS plays without arm motion |
| 2E.2 gaze | `SPOT_GAZE_ENABLED=0` | Skip arm gaze; arm stays in stowed/deployed pose |
| 2E.3 scene comments | `SPOT_SCENE_COMMENT_ENABLED=0` | Disable background YOLO + VLM loop |
| 2E.4 cloud brain | `SPOT_BRAIN_BACKEND=ollama` (or `llamacpp` post-2A) | Revert to local brain |

Hard rollback (full 2E revert): `git revert <2E-merge-commits>` on the chatbot/, tts/, animation/ subtrees. Each slice is in a separate merge so reverts are surgical.

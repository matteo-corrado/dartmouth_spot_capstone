    Model Downloads¶

    All models are downloaded locally and gitignored. Nothing is fetched at runtime except by Ollama (which caches models after the first pull).

    Summary Table¶

    Model Size Location Setup Command
    Kokoro TTS (v0.19) ~340MB models/tts/kokoro-en-v0_19/ python scripts/setup_kokoro.py
    KWS Wake Word (zipformer int8) ~5MB models/kws/ python scripts/setup_kws.py
    YOLOv8n (person detection) ~7MB auto-downloaded by ultralytics first use
    YOLO-World v2 (open-vocab) ~28MB auto-downloaded by ultralytics first use
    qwen2.5:7b (text LLM) ~4.7GB Ollama cache (~/.ollama/) ollama pull qwen2.5:7b
    qwen2.5vl:7b (vision LLM) ~4.7GB Ollama cache (~/.ollama/) ollama pull qwen2.5vl:7b
    Riva Canary-Qwen-2.5B (ASR) ~5GB Riva Docker volume bash riva_init.sh

    Total disk usage: approximately 15GB across all models.

    TTS: Kokoro (sherpa-onnx)¶

    The Kokoro-en-v0_19 model provides high-quality neural text-to-speech with 11 English speakers. It runs on CPU via sherpa-onnx (no GPU needed).

    python scripts/setup_kokoro.py

    This downloads and extracts the model pack (~340MB) to models/tts/kokoro-en-v0_19/. The download streams directly into tar extraction to avoid doubling disk usage.

    Contents after setup:

    models/tts/kokoro-en-v0_19/
    model.onnx       # ~330MB neural TTS model
    voices.bin        # Speaker embeddings
    tokens.txt        # Tokenizer vocabulary
    espeak-ng-data/   # Phonemizer data

    The default speaker is af_sarah (speaker ID 3), a warm American English female voice. Speaker can be changed in src/voice_control/spot_tts.py.

    Verify:

    python src/voice_control/spot_tts.py

    Wake Word: sherpa-onnx KWS¶

    The keyword spotter detects "Hey Spot" in streaming audio with near-zero latency. Uses a zipformer model trained on GigaSpeech XL, int8 quantized.

    python scripts/setup_kws.py

    This downloads individual model files (~5MB total) from HuggingFace to models/kws/ and creates keywords.txt with the BPE-encoded "HEY SPOT" keyword.

    Contents after setup:

    models/kws/
    encoder-epoch-12-avg-2-chunk-16-left-64.int8.onnx
    decoder-epoch-12-avg-2-chunk-16-left-64.int8.onnx
    joiner-epoch-12-avg-2-chunk-16-left-64.int8.onnx
    tokens.txt
    bpe.model
    keywords.txt    # Generated by setup script

    Verify:

    python scripts/setup_kws.py --check

    Test with microphone:

    python src/voice_control/wake_word.py --test-mic --device 24

    YOLO: Object Detection¶

    YOLO models are used for visual navigation ("go to the red chair") and person following. They are managed by the ultralytics package and auto-downloaded on first use.

    • YOLOv8n (~7MB) -- fast person detection for follow mode (class 0 = person)
    • YOLOv8s-worldv2 (~28MB) -- open-vocabulary detection for arbitrary objects

    Both run on CPU to keep GPU free for LLM/VLM inference.

    No manual setup needed. On first run, ultralytics downloads the weights to the project root. They are gitignored.

    LLM / VLM: Ollama¶

    Ollama manages the text and vision language models. Models are stored in Ollama's cache directory (~/.ollama/models/).

    ollama pull qwen2.5:7b       # Text LLM for command interpretation
ollama pull qwen2.5vl:7b     # Vision-Language Model for scene description

    These two models share GPU VRAM. Ollama automatically swaps them as needed:

    • qwen2.5:7b is loaded at startup and kept warm for 30 minutes between requests
    • qwen2.5vl:7b is loaded on-demand when a visual query is made (first load ~15s, then ~5s warm)

    To check installed models:

    ollama list

    Riva ASR: Docker¶

    The Riva ASR model (Canary-Qwen-2.5B) is managed entirely through Docker. It is downloaded and optimized during riva_init.sh (part of the Software Setup). No separate model download step is needed.

    The optimized TensorRT engines are stored in the Riva Docker volume and persist across container restarts.
